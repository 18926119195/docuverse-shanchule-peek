### 怎样观测和纠偏

借用钱学森《工程控制论》的工程视角，把开发目标、输入、可观测状态、反馈和纠偏落实到协作与验收。每次变更都应能沿这条链回查。

| 项目 | 本仓库的检查点 |
| --- | --- |
| 输入 | bookKey、正文、问核和目录范围 |
| 输出 | 候选路径、槽号映射与 A1 全局文件 |
| 可观测验收 | 50 页夹具按 8／8／34 调度，槽号可回查，不截断 A1 样本文本，拒绝非本批名词 |
| 偏差处理 | 对照带 peek 的 kanzheli 时固定语料、问句、模型和页数。记录调用预算与入模 keys；名词表接入主链前保留模块验证及调用证据。 |

在仓库根目录运行以下命令。当前离线夹具覆盖OCR 分段、A1 导出、词表硬闸、窗内别名、词面排序和三态。真实模型、OCR 和生产部署的行为需要有相应环境才能验证。

```sh
npm ci --ignore-scripts
npm run build
npm run check:system
```

提交 PR 时附时间线编号、基线提交、实际入口、预期与实测。如果实测偏离预期，用同一输入记录最小复现并附相关台账或模型请求中的非敏感字段。行为修正通过同一检查后，将决定、代码和结果补回时间线。已发布版本出现回归时，先保留失败证据，再由维护者评估回退对应变更或修正向前。
