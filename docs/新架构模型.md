# 新架构模型

**地位**：目标架构共识（人脸 / 机器脸 · 时空坐标 · 过程先验）。  
**相对现码**：现码已具备人脸门牌与 path 结算；机器脸 Residual 过程态尚未产品化捕捉。  
**非目标**：不把本文写成 HoTT 运行时说明书；HoTT 仅作类型/路径精神上的灯塔。

相关现码文档：`docs/ARCHITECTURE_EVOLUTION.md`、`docs/EXPERIMENT_NO_PEEK.md`。

---

## 1. 一句话

人脸给出**题与原料**；机器脸用 **KV 管空间座位**、用 **Residual/hidden 演化管真正动作**；可复用的是带类型的**过程路径**（接得上才当前提，接不上则拒收并记账），而不是越堆越长的语义正文。

---

## 2. 双脸 · 时空坐标

| 层 | 名称 | 绑定什么 | 角色 |
|----|------|----------|------|
| 人脸 | 用户问题 \(Q\) | `queryKey` 等问线门牌 | 题面 |
| 人脸 | 真实原料 | 书 / OCR / atom · `bookKey` / strand / corridor | 证据实体（外部门牌空间） |
| 机器脸 · 空间 | KV（及 token 位） | 历史上「哪些座位放过什么」的可读几何 | 工作记忆总线；可缓存、可分析 |
| 机器脸 · 时间 | Residual / hidden **演化** | 各层残差随位置被改写的轨迹 | **真正的分析步骤**；迁移与持续学习发生在这里 |

### 读法

```
人脸：Q + 原料门牌
        ↓ 投喂 / 调度
机器脸·空间（KV 位）：桌上摊开的可读痕迹
        ↓ 注意力读取对象
机器脸·时间（Residual 演化）：怎么推 → 下一状态 / 下一 token
        ↓ 结算外显
path / prospect / infer（人脸可读的过程账）
```

### 两层「空间」（勿混成一层）

1. **外部门牌空间**：`bookKey` / strand / corridor —— 给人与台调度、可闸。  
2. **内部座位空间**：KV 位 —— 给模型注意力；DeepSeek Context Caching / Flash 类优化主要落在这一层。

持续**不忘情节** → 管两层空间。  
持续**学会怎么推** → 动机脸时间轴（Residual 过程态）。

---

## 3. 对象 vs 步骤（迁移发生在哪）

| | 是什么 | 类比 |
|--|--------|------|
| Token / 原料门牌 | 实体 | 试卷上的题与摘录 |
| KV | 实体进模型后的**可读痕迹**（从隐状态投影出的 K/V） | 摊在桌上的笔记复印件 |
| Residual / hidden 演化 | **分析步骤**（状态转移） | 解题时的推演过程 |

- **KV 可以当分析对象**（回看当时桌上有什么），也可以当工程缓存。  
- **真迁移能力在 Residual**：换题后仍有用的是「怎么改写内部状态」的过程，不是把旧 KV 整桌搬过去。  
- 长任务「持续学习」应从 **Residual** 入手，而不是从 KV 入手；KV 保广度，Residual 保进化。

---

## 4. 过程先验：两种注入

过程先验 = 告诉模型「以前这样推过」——作为前提接着用，或作为禁区别再走。  
**不是**把历史 messages 再灌一遍（那是内容记忆）。

### 方式 A · 当前位注入（残差 / 转向）

- 旧轨迹 → 压成过程指纹或转向向量 \(v\)  
- 新问题正常成序列，在**已有位置**上：\(h \leftarrow h \pm \alpha v\)  
- **不增加** token / key 位 → **基本不占注意力窗口长度**  
- 语义：抽象过程的推力或排斥  
- 工业现实：需自托管、可改前向；闭源 Chat API 通常不可用

### 方式 B · 旧位挂回（激活 / KV 前缀续写）

- 恢复旧序列位置上的状态（产品上主要是 **KV**）  
- 新问题接在同一条链后，新 token **attend 旧位**  
- **占有效上下文长度**；省的是重算/重发，不是注意力席位归零  
- 语义：同一具体推理链上接着干  
- 工业现实：会话 KV、DeepSeek Context Caching / V4.1-Flash 压缩 KV 等属这一族

| | A 当前位 | B 旧位挂回 |
|--|----------|------------|
| 过程先验？ | 是（抽象过程） | 是（具体链续写） |
| 占注意力位 | 基本不占 | 占 |
| 更贴「持续学习过程」 | 是 | 弱（偏工作记忆） |
| 与 Flash 缓存 | 不同层 | 同族 |

**主攻持续学习**：A（及 A 的外显近似）。  
**主攻省预填、同会话续写**：B。

## 5. 具体路径 vs 可复合关系（类型闸）

### 存下来的激活轨迹是什么

- 是某次生成动作在**具体序列实例**上的求值（具体、函数式的关系显影）。  
- 同权重 + 同输入序列 + 同设定下可复现、可指认。  
- **可复现 ≠ 可注入到任意新问题上**。

### 定义域 / 接纳

新问题是新的序列实例。旧路径 \(\gamma\) 绑在旧布局上。

- **接得上** → 可以 \(\gamma\) 为前提下推。  
- **接不上** → \(\gamma\) 仍是真迹，但不能合法当本次前提。

「语义相关」只说明**值得尝试复用**，不自动保证落在定义域内。

### 拒收即监督（校对，而非神话）

协议建议：

```
尝试：路径 γ 是否接纳新问题实例？
  → 接纳：以此为过程前提（A 或 B）
  → 拒收：不用，记账「此路径不可作前提」
```

- 增益：挡住错位过程灌入；可审计；利于管理**错误复用**类幻觉。  
- 信号应标成：**「不能复用路径 γₙ 作为前提」**。  
- **不要**直接标成：「内部不存在相关推理 / 用户一定错了」——除非另有「新跑 γ' 与旧 γ 是否同族」的对比层。

精神近于「带类型的过程见证：well-typed 才复合」；不必字面实现 HoTT。

## 6. 双输入端口（目标服务契约）

未来推理入口宜显式两端口（自建栈时）：

| 端口 | 内容 |
|------|------|
| A | 新的用户问题（人脸） |
| B | 复用状态：`pathId` / 过程指纹 /（高级）转向或会话 `state_id` |

常规 Chat API 只有 messages 文本端口 → **B 在产品上先落成 path / 门牌回放**；真 Residual 注入留在自托管演进。

## 7. 与现码 Docuverse 的映射

| 新架构模型 | 现码近似 |
|------------|----------|
| 人脸 · 原料空间 | `bookKey` / strand / corridor / Toc · semantic |
| 人脸 · 问线 | `queryKey`、decide / prospect |
| 过程账（外显路径） | `pathKey` = infer × prospect；reuse 走 neighbour→旧问线 path |
| 增量三态闸 | `unread` / `sufficient` / `insufficient` |
| 有序阅读进度（可选） | 投喂材料相对原文的有序覆盖（LCS/区间）；锚门牌，不锚「读心」 |
| 机器脸 · KV | 未自管；依赖上游 API 前缀缓存时属 B |
| 机器脸 · Residual 过程态 | **尚未捕捉**；长期传感器 / 转向 / 指纹挂 `queryKey`·`pathKey` |

现实验分支（无 peek）：材料父门 = `bookKey`；`toc_nav` 为结构 agent 选读界——属人脸侧「先地图后精读」，与过程先验互补。

## 8. 分层落地路线

1. **现在（人脸 + 外显过程）**  
   门牌调度、三态、path 结算与复用、拒收/不足扩窗；记忆在台侧，少污染模型窗口。

2. **中期（过程先验的便携近似）**  
   `Q → pathId` 绑定；复用只回放 path 指向的材料与结构；可选有序覆盖作进度条。

3. **远期（机器脸时间轴）**  
   同模型自托管：记录 Residual 轨迹指纹；挂到同一 `queryKey`/`pathKey`；尝试方式 A 转向；拒收作类型闸。  
   方式 B 仅作会话工作记忆，不当「学会」的本体。

---

## 9. 禁止混淆

| 不要当成 | 实际是 |
|----------|--------|
| Flash/Context Cache = 过程先验 A | 那是 B 族（前缀 KV） |
| 历史 messages = 推理过程 | 内容记忆；过程常未写进字里就丢 |
| 整段激活原样注入 = 通用过程信号 | 位置绑死；要的是压缩指纹/转向 |
| Residual 捕捉 = 可读自然语言思维 | 张量轨迹可准记；语义标签需另探针 |
| 拒收 = 用户语义必错 | 仅「此具体路径不作前提」 |
